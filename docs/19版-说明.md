# 19 版说明（r19）

两个目标：**首页按设计稿 1:1 还原**，以及**把"进房间还有点卡顿"真正定位到根因并修掉**。

---

## 一、卡顿：找到真正的根因了

前几版一直在调平滑参数、换插值方式，方向是错的。这次把"自己的车每帧走了多远"按来源分层拆开量（L0 服务端位置 / L1 速度前馈 / L2 画出来的位置），才定位到手。

### 根因：残差校正用了错误的方向，一直在跟正常移动较劲

`src/coop.js` 的 `_absorbResidual` 负责把"客户端预测位置"和"服务端权威位置"的偏差慢慢消化掉。它需要知道"车正在往哪个方向走"，原来是这样算的：

```js
const vx = Math.sin(this.me.yaw) * this.me.speed;   // ❌ 用「车头朝向」
const vz = Math.cos(this.me.yaw) * this.me.speed;
```

但**车头和实际位移方向是两件不同的事**：

- 位移是**立即**沿输入方向走的（`core/motion.js` 里 `body.x += ux * speed * dt`）
- 车头是 8 rad/s **慢慢追**过去的，要 0.1~0.2 秒才齐

两个必然分叉的场景：

| 场景 | 车头 | 实际位移 | 偏差 |
|---|---|---|---|
| 撞墙沿墙滑行 | 朝输入方向（可能 70°） | 沿墙面 | **70°** |
| 刚改方向的那 0.15 秒 | 还在旧方向 | 已经沿新方向 | 45°~90° |

方向错了，残差就被拆错：本来属于"纵向"（预测正常的领先量，不该追）的那部分被算成了"横向"（真偏差，要追）。于是每帧都在推 `me` 2 厘米——而渲染外推 `want = me + v*acc` 里的 `me` 带着这 2 厘米，软约束又把它逐帧抄给 `_disp`。

**实测证据**（110fps，直行 5 秒）：

```
shift: 1.071 1.095 1.189 1.065 1.091 1.109 1.189 1.070 ...
         ↑ 残差一直顶在保险丝 1.2 米上，从不下来
```

### 修法

1. **运动方向改用实测位移 `_vel`**（上一个 tick 真正走了多远 / 时长），和渲染外推用同一个量，两边不会打架。撞墙滑行、地形减速、刚改方向全都自动正确。`_vel` 还没测出来时（起步第一帧）才退回车头方向。
2. **给纵向领先量加封顶 `LEAD_CAP = 1.15` 米**。领先 0.2~0.4 米是预测的正常代价不该追，但"不追"不等于"不封顶"——网络抖动会让它一路攒到保险丝上顶着。

### 效果（真实 `Room` + 真实 `NetClient`，同一套场景）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 自己每帧位移变异（延迟 30ms） | **61.1%** | **0.0%** |
| 自己突变帧占比 | **1.5%** | **0%** |
| 自己 p99 位移 | 0.354 米 | 0.080 米 |
| 自己每帧位移变异（延迟 60ms ±10ms 抖动） | **32.1%** | **0.0%** |
| 残差（30 / 80 / 150ms 三档延迟） | 恒定 1.19 米 | **全部 0.000** |

`61%` 的变异就是用户说的"卡顿"——每帧走的距离忽大忽小，画面上就是一顿一顿。

## 二、顺手修的三个真问题

### 1. 震屏偏移没撤销，相机会漂

```js
// 修复前：震屏直接加进 cam.position，下一帧的指数趋近把它当成"真实的落后量"去追
cam.position.x += Math.sin(t * 61.7) * amp;
```

开炮后镜头会晃半天才回来。改成记下偏移量、下一帧先撤掉。

### 2. 高刷屏的速度估计量化到 30Hz

`_vel` 在"本帧没有推进 tick"时（120Hz 下大约一半的帧）保持旧值不变，实测出现 `0 / 15 / 0 / 15` 的锯齿，变异最高到 159%。这一项其实不直接造成画面抖动（画出来用的是 `_disp`），但会污染残差拆分——修完方向问题后变异已经归零。

### 3. 矮屏（1366×768）首页看不到榜单和键位

之前用 `display:none` 让位，等于这两个功能在笔记本上不存在。改成 `scale(.82)` 整体缩一档，缩也要看得见。
