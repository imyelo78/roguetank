# PVE 玩法设计案（v1）

> 定位：在现有"无限波次肉鸽生存"核心之上扩展 PVE 内容深度，优先复用已有系统
> （波次调度 / Boss 框架 / 强化卡池 / 预警圈机制），避免重造轮子。

## 一、现有模式定位

现有核心循环（清波 → 三选一 → 军械 → Boss）已经完整，问题在于**目标单一**：
玩家永远在做同一件事，缺乏"为什么打"的叙事与变奏。以下按投入产出比排序。

## 二、新增玩法（按优先级）

### P0 · 挑战词条（Run Modifiers）—— 成本最低，变奏最强

每局开局随机 1 条全局词条（后续可让玩家自选难度），改变整局规则：

| 词条 | 效果 | 补偿 |
| --- | --- | --- |
| 钢铁风暴 | 炮击间隔 7s → 4.5s | 得分 ×1.3 |
| 弹药告急 | 全局射速 -20% | 清波奖励 ×1.5 |
| 精英猎场 | 每波必出精英 | 精英分 +200 |
| 迷雾战场 | 视距减半（雾浓度拉高） | 击杀分 ×1.4 |
| 军备竞赛 | 敌人血量 +30%/波 | 军械补给改为每 2 波 |

实现：纯数据 + 在 `Game.startWave/_updateWaves` 里读词条系数，约 1 天。

### P1 · 每日挑战（Daily Seed）

- 用当日日期做随机种子（`mulberry32`，level.js 已有同款），全玩家同地图、同刷怪序列、同强化卡池。
- 结算上传分数到排行榜（Cloudflare Pages Functions + KV 即可，无需独立服务器）。
- 每天只有 1 次正式成绩，可无限练习模式（不计分）。
- 实现：种子注入 `Math.random` 代理 + 一个 Worker API，约 2~3 天。

### P2 · 守卫目标模式（/objective wave）

在清波之上叠加"要保护的东西"，强制走位、终结龟缩：

- **守卫补给站**：地图中央刷一辆不可移动的 APC（血量随波次），被击毁则本局结束；敌人 AI 优先级 = 玩家 > APC。
- **护送车队**：每 5 波一辆车队沿固定路线移动，玩家需清出通道。
- 奖励：目标存活到 Boss 波，Boss 战中每 10 秒呼叫一轮支援炮击（反向利用现有 strikes 系统）。
- 实现：复用 Enemy/Tank 实体 + 新增 target 实体与 AI 权重，约 3~4 天。

### P3 · 敌人扩展（Roster）

| 敌人 | 行为 | 反制 |
| --- | --- | --- |
| 自爆无人机 | 低空飞行、俯冲自爆（无视掩体高度） | 只能打掉，逼走位 |
| 炮台 | 固定刷新、超远射程、预警线指示 | 必须主动拔点 |
| 补给车 | 给周围敌人回血，会逃跑 | 优先击杀有额外分 |
| 重盾兵 | 正面 80% 减伤，背后无减伤 | 绕后（复用侧翼 AI） |

实现：全部走现有 `type` 分发 + `Enemy` 状态机加分支，每个约 0.5~1 天。

### P4 · 双人合作 PvE（Co-op）

- 架构：WebSocket 权威服务器（Node + ws），主机模拟、从机上报输入；快照同步 10Hz + 插值。
- 肉鸽资源独立（各自强化卡），波次奖励共享；一人倒地队友可救援（10 秒窗口）。
- 部署：复用 Cloudflare Workers + Durable Objects 承载房间，免运维。
- 实现：工程量 1~2 周，建议在 P0~P2 验证完手感后再启动。

## 三、数值与经济原则

1. 词条类补偿系数控制在 1.3~1.5 倍，避免"打词条 = 必选"。
2. 每日挑战种子必须可复现：**所有** `Math.random()` 调用点（抽卡/刷怪/AI 抖动）都要走代理。
3. 新敌人数值锚定现有曲线：普通敌 `55 + n×14` HP，新敌人按"威胁度 = DPS × 生存时间"折算。
