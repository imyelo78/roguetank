# 15 版说明：先把"到底哪版在抖"变成可验证的事实

这一版**没有继续改渲染算法**。原因写在下面，全是实测数据，不是感觉。

## 一、我做了什么

上一版（14 版）之后，用户反馈"越做越差，之前的版本抖动控制要好很多"。我没有继续叠代码，而是搭了一套**可复现的量化装置**，在同一个服务端、同一份协议、同一个渲染循环下，把三个版本跑了同一组用例：

- 自己的车：静止 3 秒 + 直行 3 秒（清空建筑和敌人，排除撞墙与受击干扰）
- 远端敌人：同一时间段内每帧的位移
- 输出两个指标：**每帧位移变异系数**（越小越平滑）、**零位移帧占比**（越高越"定格跳"）

### 结果

| 版本 | 自己车·直行变异 | 远端敌人·零位移帧 | 远端变异 | 插值夹死 |
| --- | --- | --- | --- | --- |
| 12 版 | 0.89% | **41%** | 125% | 273 |
| 13 版 | — | — | — | 同 12 版 |
| **14 / 15 版** | **0.00%** | **0%** | **11%** | **2** |

结论很硬：**14 版的渲染链路已经是三条里最好的**。自己的车静止位移严格为 0、匀速直行每帧位移恒定到小数点后五位（变异 0.00%），远端敌人没有一帧定格。

同一套用例下，12 版有 41% 的帧"敌人完全不动"，然后突然跳一格 —— 这就是"敌人一跳一跳"的来源，14 版把它修掉了（夹死 273 → 2）。

所以这次我**没有动 `_disp` / `_reconcile` / 插值任何一行**。中途我试过把渲染改回 11-07 那套"纯解析式外推"，实测自己车变异从 0.00% 劣化到 6%，已经回滚，代码库里没有这段。

## 二、那为什么会觉得"越做越差"

我不能替你下结论，但可以把可能性收窄成三条，并且这一版给了你判断工具：

1. **服务器上跑的不是 14 版**。服务端没重启、浏览器缓存了旧 `dist`、CDN 没刷新，现象和"新版本变差"一模一样。
2. **本机掉帧**。3~4 人同屏 + 阴影时帧率掉到 40fps 以下，看到的是卡顿式抖动，跟插值无关。
3. **插值延迟变大带来的"钝"**。14 版把远端延迟抬到约 100ms 换取连续性，有人会觉得"手感慢半拍"，把它当成"变差"。

## 三、这一版加的两个诊断设施

### 1. 构建号可见（解决第 1 条）

- 房间码浮层现在会显示构建号，例如 `房间 FW87 1/4 r15`
- 页面启动时会拉 `/healthz` 对比：**页面版本 ≠ 服务端版本** 就在顶部弹红条，写明两边的版本号
- 直接访问 `http://服务器IP:端口/healthz` 能看到 `{"build":"r15", ...}`

出问题先看这两处：有红条 = 没部署成功，不是代码问题。

### 2. 网络诊断面板（解决第 2、3 条）

**游戏里按 F3**（再按一次关闭），右上角显示：

```
fps   60         ping 42ms
snap  15.0 Hz  间隔 67/69ms
插值  3 格 100ms   夹死 0/s
停顿 1 次   模式 coop   房间 FW87
```

怎么读：

| 现象 | 说明 |
| --- | --- |
| `fps` 低于 50 且带 `⚠低帧` | 是**掉帧**，不是网络。先去设置里关阴影/降分辨率 |
| `snap` 低于 12Hz 且带 `⚠` | 服务端或链路在拖，看 `间隔` 的最大值 |
| `夹死` 持续明显大于 0 | 远端实体会定格跳帧，这才是插值问题 |
| `插值 3 格 100ms` 稳定、`夹死 0/s` | 插值健康，抖动若仍存在则不在这一层 |

## 四、怎么确认部署成功

```bash
# 1. 核对包
sha256sum <包名>
# 2. 解包覆盖（先停服务）
systemctl stop roguetank          # 或 kill 掉 node server.mjs
tar -xzf roguetank-2026-11-08-15.tar.gz -C /opt/roguetank
# 3. 依赖没变，可跳过；Node ≥ 18
cd /opt/roguetank && npm install --omit=dev
# 4. 重启
systemctl start roguetank
# 5. 一行确认服务端加载的是 r15
curl -s http://127.0.0.1:5173/healthz
# → {"ok":true,"proto":3,"build":"r15",...}
```

浏览器打开页面后：
- 房间码旁边应显示 `r15`
- 顶部**没有**红条
- 按 F3 能看到诊断面板

三项都对，说明你测的确实是这一版。

## 五、这一版相对 14 版的实际改动

只加了诊断，**没有动玩法、渲染、网络**：

- `src/core/protocol.js`：新增 `BUILD = 'r15'`
- `server.mjs`：`/healthz` 增加 `build` 字段
- `src/main.js`：页面与服务端构建号不一致时顶部红条提示
- `src/HUD.js` + `styles.css`：房间码浮层显示构建号
- `src/Game.js`：F3 面板增加 `fps` 低帧告警、`插值格数/毫秒`、`夹死/秒`

其余文件与 14 版逐字节一致（`src/coop.js`、`src/net.js`、`server/room.js`、`src/core/world.js`、`src/chassis.js`、`src/Tank.js` 全部未改）。

## 六、如果你的体感仍然"更差"

那一定是我还没抓到的第三种东西。按 F3 截个图给我，只要一行数字就能定位：

- `fps` 是多少
- `夹死` 是多少/s
- `插值` 是几格
- `snap` 是多少 Hz、`间隔` 最大多少 ms

有这四个数，就不用再猜了。
