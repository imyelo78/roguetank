# 16 版说明：主炮打不出来、车不动、视角乱跳

三个问题的根因都找到了，两个是代码 bug，一个是"看不出为什么没反应"的体验问题。

---

## 一、主炮不能发射 / 车不动：世界停在 lobby，输入被整包丢弃

### 怎么发现的

我用真实浏览器按住鼠标 2.5 秒逐帧采样，前 3 秒每次拿到都是：

```
{'firing': True, 'bullets': 0, 'state': 'lobby', 'wave': 0, 'tick': 90}
```

`firing: True` 说明鼠标按下、输入确实算出来了；`state: lobby` 说明**服务端根本没在跑游戏**。
`_updatePlayers()` 对非 playing 状态直接丢输入，所以车不动、炮不响——玩家看到的却是完整战场画面。

### 两条会永久卡在 lobby 的路径

**路径 A：服务端倒计时到点，但开局调用失败就再也不重试**

```js
// 旧代码
if (this.autoStartT <= 0 && w.players.length > 0) {
  w.start();              // 返回值从不检查
  this.startedAt = Date.now();   // 无论成功与否都打上"已开局"
}
```

`World.start()` 在 `state === 'playing'` 或没人时会返回 false。一旦碰上，`startedAt` 已被写死，
房间永久认为"已经在打了"，实际世界还在 lobby。

**路径 B：全员阵亡回大厅，倒计时被置 0**

```js
// 旧代码
w.state = 'lobby';
this.startedAt = 0;
this.autoStartT = 0;      // 等人按「开始战斗」
```

本意是"等人手动开局"，但大厅面板的「开始战斗」按钮**只在进场前可见**，
局内玩家根本找不到。于是全场永久停在 lobby。

### 修复

服务端把"该开局了"和"开局成功"拆成两件事，用 `_startPending` 挂起重试：

```js
// 倒计时走完 / 房主点开始 → 只挂起
if (this.autoStartT <= 0) {
  this.autoStartT = 0;
  this._startPending = true;
}

// 每个 tick 重试，成功了才算开局
if (this._startPending && !this.startedAt && w.players.length > 0) {
  if (w.start()) {
    this.startedAt = Date.now();
    this._startPending = false;
  }
}
```

全员阵亡回大厅改成重新起 3 秒倒计时，和刚进房间完全一样的体验。

### 现在按开火没反应，屏幕上会告诉你为什么

进场后有 3 秒等待期（等队友进来），这段时间车能看不能动。以前没有任何提示，
和"游戏坏了"无法区分。现在中间会显示：

- 进场：`战斗准备中… 3 秒后开始`
- 开局：`开战！`

## 二、视角乱跳：震屏参与了 lookAt

`CoopMode._updateCamera` 的顺序反了——先用 `Math.random()` 抖动相机位置，再用抖动后的位置算视线：

```js
// 旧代码：每帧视线被随机数掰一下，整个战场跟着旋转颤
cam.position.x += (Math.random() - 0.5) * this._shake;
this.game.camLook.set(this._disp.x, 1, this._disp.z);
cam.lookAt(this.game.camLook);
```

单机 `Game._updateCamera` 是先 `lookAt` 再叠震屏，所以单机不抖、联机抖。改成同序，且随机数换成双正弦平滑振荡：

```js
this.game.camLook.set(this._disp.x, 1, this._disp.z);
cam.lookAt(this.game.camLook);

if (this._shake > 0) {
  const t = (this._shakeT = (this._shakeT || 0) + dt);
  const amp = this._shake * 0.5;
  cam.position.x += Math.sin(t * 61.7) * amp;
  cam.position.y += Math.sin(t * 47.3 + 1.7) * amp * 0.7;
  this._shake = Math.max(0, this._shake - dt * 1.2);
}
```

## 三、车辆卡顿 / 越打越卡：`world.start()` 完全不清场

```js
// 旧代码
start() {
  this.state = 'playing';
  this.tick = 0;
  this.time = 0;
  this.startWave(1);   // 上一局的敌人、子弹、pending 全留着
  return true;
}
```

重开时第 1 波刷出来的敌人和上一局残党叠在一起，`enemiesLeft` 永远清不到 0 →
选卡不弹、波次不推进 → 敌人越积越多，帧率一路掉。

现在清场 + 玩家回出生点满血：

```js
this.enemies.length = 0;
if (this.bullets) this.bullets.length = 0;
this.pending.length = 0;
this.events.length = 0;
this.waveActive = false;
this.waveGap = 0;
this.left = 0;
this.picksOpen = false;
this.picks = null;
this.enemiesLeft = 0;
```

顺带修了出生点字段名（`_spawnX/_spawnZ`，之前误写成不存在的 `_spawn` 对象）并补了 `_spawnYaw`。

## 四、四款坦克合并成一款豹式

数值取原均衡型：**120 甲 / 15 速 / 全向炮塔瞬间对准**。

```js
export const CHASSIS = {
  panther: { id: 'panther', name: '豹式', hp: 120, speed: 15, ... },
};

export const CHASSIS_ALIAS = {
  balanced: 'panther', light: 'panther',
  heavy: 'panther', hunter: 'panther', commander: 'panther',
};

export function normalizeChassisId(id) {
  if (id && CHASSIS[id]) return id;
  const alias = CHASSIS_ALIAS[id];
  return (alias && CHASSIS[alias]) ? alias : 'panther';
}
```

历史 id 全部映射过去，老存档 / 老客户端 / 老排行榜不会变成"未知车体"。

**这一版补了一个漏**：服务端 `addPlayer()` 之前把原始 id 原样存进 `p.chassis`，
`balanced` 这种历史 id 会一路传到客户端，尺寸表查不到就退回默认尺寸，各端看到的大车小车不一致。
现在入口处就归一化。

`Tank.js` 尺寸表四款键统一指向同一个 `PANTHER` 对象（旧键保留为别名）。

## 上线注意

**必须重启服务端进程。** 只替换 `dist/` 不重启的话，`/healthz` 还会报旧版本，页面会弹红条
（这是 15 版加的版本自检，就是为了不再"测到旧包却不知道"）。

确认方法：

```bash
curl -s http://你的域名/healthz | grep -o '"build":"[^"]*"'   # 应输出 "build":"r16"
```

页面左下角房间码旁也应显示 `r16`。

### 关于静态资源缓存

当前配置（`server.mjs` 与 `deploy/nginx.conf` 一致）：

| 类型 | Cache-Control |
| --- | --- |
| HTML | `no-cache` |
| JS / CSS | `public, max-age=300, must-revalidate` + ETag（size+mtime 派生） |

也就是说 JS/CSS **5 分钟内不会发请求**，5 分钟后带 ETag 问一次、没变就 304。
ETag 随文件覆盖必变，所以真正导致"测到旧包"的通常是**服务端进程没重启**或**反代/CDN 缓存**，不是这个 5 分钟。

如果你希望改版后立刻生效（代价是每次加载多几个 304），把 JS/CSS 也改成 `no-cache` 即可，一行配置的事，说一声我改。
