# 14 版 · 联机抖动彻底修复 + 三个回归修复

> 基线：**12 版功能全集**（房间生命周期、全向炮塔、房间码校验、autoStart 全部保留），
> 不使用 13 版。13 版是「12 版外壳 + 08 版内核」的混搭，把 12 版修好的东西冲掉了一批。

## 一、为什么之前一天都没修好

从 08 到 13 版，所有补丁都落在**自己那辆车的本地预测 / 残差校正 / 外推**上
（`coop.js` 的 `_absorbResidual`、`_vel`、`_disp`）。但用户最后说的是「**所有东西都在抖**」——
敌人、队友、子弹一起抖，这不是单车预测能解释的。

真正的病根在 `src/net.js` 的**远端实体插值**：

| 项 | 实际值 |
| --- | --- |
| 服务端 tick | 30Hz（33.3ms / 格） |
| 快照 | 15Hz（66.7ms / 帧，相邻帧 tick 差恒为 2） |
| 插值延迟 `_interpTicks` | 被网络抖动自适应抬到 **3~4 格**（100~133ms） |
| 快照缓冲 | **只留 `prevSnap` / `lastSnap` 两帧**（可插值区间仅 2 格 / 66.7ms） |

延迟退 3~4 格，游标落在更早的段里，但缓冲只覆盖最新那一段，于是每帧都被
`Math.max(minTick, ...)` 夹死在 `prevSnap.tick` 上，`alpha` 恒为 0；
直到下一条快照到达才整段跳一格。**远端实体每 66ms 跳一格 = 整个场景在抖。**

线上探针实测：

```
快照数=89 间隔 均值=66.6ms 最大=69.4ms hz=15.0
tick差分布={"2":88}
overshoot=2.8 jitter=1 => interpTicks=3 delay=100ms
⚠ 一周期内 renderTick 被夹死比例=100%
renderTick 范围: -3.00 ~ -1.00 格，而可插值区间是 -1 ~ 0
```

12 版和 13 版都存在，所以「退回 08 内核」「改预测参数」都不可能修好。

## 二、这次改了什么

### 1. `src/net.js` — 插值链路重写（抖动根因）

- **8 帧快照历史缓冲**（`snaps` / `SNAP_BUF = 8`，约 0.5 秒），`lastSnap` / `prevSnap`
  保留为缓冲尾部视图，兼容 `coop.js` 既有读取。
- `sample()` 不再固定取最后两帧，而是在历史里找**真正跨越渲染游标**的那一对快照
  `A → B` 做插值；`_renderTick()` 的下界改用缓冲最老 tick。
- **子弹一并插值**（旧版直接用最新帧，同样每 66ms 跳一格）。
- **平滑服务端时钟** `_serverOffset`：渲染游标挂在低通滤波后的「服务端 tick 时间轴 ↔
  本地时钟」偏移上，快照只提供位置、不负责计时。单条快照早到 / 晚到不再直接把
  游标推来推去。
- **延迟连续过渡** `_interpDelay`：`_interpTicks` 在 3↔4 切换时以 400ms 时间常数
  平滑趋近，避免切换那一帧把游标瞬间拉回 1 格（33ms 位移）。
- `gapMax` 改为**可衰减**（`×0.97` / 帧）。旧版是历史最大值，一次偶发 70ms 抖动
  就把延迟永久顶高，网络恢复平滑也退不回来。
- `_updateInterp()` 的延迟上限显式受缓冲深度约束，防止以后调小 `SNAP_BUF` 又夹死回去。
- 拒绝 tick 不递增的乱序 / 重连补帧；`welcome` / `close` 完整重置新状态。

### 2. `src/coop.js` — 敌方血条恢复

联机敌人创建的是 `Tank` 类，而血条只在单机 `Enemy` 类里创建，所以**联机敌人压根没有
血条对象**；协议里的 `e.hp`（0~100 百分比）也一直没被消费。

- 按 `Enemy.js` 同样的尺寸 / 配色补一套共享几何与材质的头顶血条（`Tank.dispose()`
  只 remove 节点、不释放共享资源，正好配套）。
- `_applySnapshot()` 每帧用 `e.hp` 更新 `barFill.scale.x` / 位置，并 `bar.lookAt(camera)`。
- BOSS 仍用 HUD 顶部长条，不重复挂（与单机一致）。
- 精英车用金色填充，车体缩放用 `1 / scale` 抵消，四车血条尺寸一致。

### 3. 波次 / 通关流程

12 版基线的服务端清波 → 发卡 → 选卡 → 下一波链路本身是好的，13 版新加的
`world.reviveAll()` 会把 `this.wave = 1` 重置，`over` 分支又会 `reviveAll(); w.start()`，
于是「通关 / 全灭」后被打回第 1 波。14 版**不引入该方法**，保留 12 版的
`_respawnPlayer()` + 回大厅等人点「开始战斗」。

## 三、验证结果

### 确定性仿真（真实 `NetClient` + 真实 `encodeSnapshot/decodeSnapshot`，60fps）

| 场景 | 12 版停滞帧 | 14 版停滞帧 | 12 版突变帧 | 14 版突变帧 | 夹死 |
| --- | --- | --- | --- | --- | --- |
| 稳态 ±3ms 抖动 | 238 | **0** | 114 | **0** | 406 → 2 |
| 大抖动 ±15ms | 234 | **0** | 87 | **0** | 396 → 2 |
| 每 8 条丢 1 帧 | 280 | **0** | — | **0** | 470 → 4 |

14 版 alpha 严格单调推进再回绕：`0.46 0.70 0.94 → 0.19 0.43 0.69 0.95 → ...`

### 真实浏览器 A/B（Chromium + swiftshader，12 版 :5174 / 14 版 :5175）

| 指标 | 12 版 | 14 版 |
| --- | --- | --- |
| alpha 恒 0 | 157 / 180 | **2 / 180** |
| alpha 帧帧推进 | 44 / 179 (24.6%) | **177 / 179 (98.9%)** |
| 插值夹死增量 | 333 | **9** |
| 快照缓冲深度 | 无（两帧） | **8** |
| 敌方可见血条 | 0 / 4 | **4 / 4** |
| 静止时相机 / 自车波动 | 0.0000 | 0.0000 |
| JS 报错 | 无 | 无 |

> 说明：headless swiftshader 实测只有约 **5.5 fps**（帧间隔中位 190ms），WebSocket
> 回调被渲染阻塞挤成 `[99, 100, 3.8, 96.6, 100.6, 0.1]ms` 的突发，因此浏览器里采到的
> alpha 序列存在采样混叠，**不能**拿来判断平滑度；平滑度以上面的 60fps 确定性仿真为准。
> 浏览器验证用于确认代码加载、夹死计数、血条 3D 对象、相机与无报错。

## 四、明确保留的既有功能

- `light` / `hunter` 全向炮塔（`FULL_TRAVERSE = 180`，`rate: 170`），
  `hp / speed / turn` 数值**不变**；猎手为顶部独立旋转炮塔模型。
- 房间生命周期：`EMPTY_GRACE_MS` 3 分钟全员离线宽限、房主移交、
  `room-expired` 主动通知、真实 `autoStart` 倒计时。
- 房间码：自定义 4 位码、`ROOM_CODE_RE` 校验、不做 `O→0→2` / `I→1→J` 链式替换、
  删除误导性的 `in-game` / `not-started` 文案，允许中途加入。
- 快照节奏：`SNAPSHOT_RATE = 15`、`TICKS_PER_SNAP = 2`，按 tick 计数发帧。
- 自己那辆车的预测 / 残差校正 / 相机跟随完全沿用 12 版，未改动。

## 五、部署

```bash
npm install          # 或沿用现有 node_modules
npm run build        # 可选，重新生成 dist/
node server.mjs      # 默认 5173，可用 PORT=xxxx 覆盖
```

静态部署直接用 `dist/`。升级时**整目录替换**，注意浏览器对 `.js` 有 5 分钟
`max-age=300` 缓存 + ETag 协商缓存；HTML 是 no-cache，刷新后会自动拉新 ETag。
