## 二、0 分上榜：已修，并清了存量

### 现象与原因

线上总榜确实有一条：

```json
{ "name": "gunner", "score": 0, "wave": 1, "kills": 0, "players": 1 }
```

来源是「点了开始、还没开打就被撞毁」——这一局真的发生了，但它不是成绩。
`normalizeEntry` 对分数只做上限钳制（`num(body.score, 99999999)`），
没有下限，0 分就这么进来了。

### 三层拦截

只拦一处都会漏，所以三层都做了：

| 层 | 位置 | 行为 |
|---|---|---|
| 提交 | `handlePost` | `score <= 0` 直接 400 `no-score`，不写存储 |
| 读取 | `handleGet`（今日榜 / 总榜 / stats） | 过滤掉不合格条目，存量脏数据也不显示 |
| 存量 | `server/score-cleanup.js`，启动时跑 | 真正从 `.data/scores.json` 删掉 |

前端也同规则：

* `submitScore` 遇到 0 分**不上传、不写本地、不进补传队列**
* 结算页显示「0 分不计入榜单，再打一局就能上榜」，而不是「云端同步失败」
* `readLocal` 读旧 `localStorage` 时清掉 0 分并写回（老版本存进去的会一直显示）
* `flushPending` 丢弃队列里的 0 分（否则每次启动都重试一遍，永远清不掉）

### 门槛只卡 0 分，不设更高

1 分也是真实残局（旧站那条 `selftest` 就是 1 分）。门槛一抬高就开始误杀，
所以规则就是 `score > 0`。

### 实测（用线上 5 条数据原样复现）

```
[clean] 清掉 2 条无效成绩（0 分），涉及 2026-11-09；总榜现有 4 条
[legacy] 旧站成绩已并入：8 条 / 4 天，总榜现有 12 条
```

总榜：

```

 2 78          476,371
 3 91           41,936
 4 114114       28,435
 5 gunner       10,625
 6 高达1号      10,105
 7 siiiu         6,800

10 gunner        5,400
11 gunner          140

```

那条 0 分没了，1 分的 `selftest` 保留（它是你列的表里的一条）。

提交侧验证：

```
POST {"name":"测试0分","score":0,...} → {"ok":false,"reason":"no-score"}
POST {"name":"测试5分","score":5,...} → {"ok":true,...}   # 5 分正常上榜
```

本地脏数据验证：往 `localStorage` 塞一条 0 分 + 一条 999 分，刷新后
页面上只有 999 分那条，`localStorage` 里的 0 分也被删掉了。

所以规则只放在入口和读取处。

8 项里 5 项立刻失败；改回来全绿。
