# 20 版说明（r20）— 开局冻结 3 秒的真正原因

19 版发到线上后我实测了 `https://roguetank.i1978.com`，**又抓到一个比之前所有抖动都严重的 bug**。

---

## 一、症状

点「开始战斗」之后：

- **队友 / 敌人 / 子弹定格约 3 秒**，之后突然"追上"
- 自己的车**还能动**（因为是自己本地预测画出来的）
- 所以第一眼看像"别人卡了"或者"网络差"，极容易被误判

---

## 二、定位过程（线上实测）

### 第一步：服务端没问题

直连 WebSocket 量快照节奏：

```
快照间隔: 均值66.7ms 变异2.9% min63 p50 66 p95 70 max71
最长停滞: 1 条连续同 tick
```

服务端 15Hz 稳得很，tick 严格递增。**不是服务端卡**。

### 第二步：问题在客户端收包

在页面里挂钩 `_emit('snap')` 记录每一条到达：

```
20 秒内收到 299 条快照
平均间隔 66.7ms  最大 71ms      ← 全部准时到达
tick 步长≠2 的位置: 45 处        ← 但 45 次的 tick 不前进
```

**消息都到了，但 tick 重复了**。而且是集中在一段：

```
{'start': 3092, 'tick': 90, 'n': 45, 'state': 'lobby', 'end': 6027}
                              ↑ tick=90 卡了 45 条 ≈ 3.0 秒
```

### 第三步：直接驱动服务端复现

```js
i=85   tick=86  state=lobby     lastSnapTick=86
i=90   tick=1   state=playing   lastSnapTick=90   ← 归零！
i=95   tick=6   state=playing   lastSnapTick=6
```

**`world.start()` 把 tick 归零了**，而 lobby 阶段已经跑到 86。

### 根因

`src/net.js` 收快照时有一道防乱序的闸门：

```js
if (entry.tick > this.snaps[this.snaps.length - 1].tick) { 接收 }  // ❌
```

开局后服务端从 tick=1 重新数，客户端认为"这几十条全比 86 小 = 全是乱序包"，
**全部丢弃**。要等服务端 tick 重新爬过 86（≈2.9 秒）才恢复接收——

- 这 3 秒里，队友/敌人/子弹的位置数据一条都不更新 → **画面定格**
- 恢复的瞬间 `_serverOffset` 因为 tick 时间轴换了基准而跳变约 3000ms
- 渲染游标（`want`）一口气超前 **60 多格**，之后好几秒都在夹死

实测游标位置，修复前是这样的：

```
{'ms': 2007, 'lead': 2.9,  'fz': 8}
{'ms': 2507, 'lead': 18.0, 'fz': 38}
{'ms': 3007, 'lead': 32.7, 'fz': 68}
{'ms': 4007, 'lead': 62.9, 'fz': 128}   ← lead 越跑越远，frozen 每帧都涨
```

---

## 三、修复

`src/net.js`：识别"tick 明显倒退 = 新一局"，整段重置。

```js
const RESET_GAP = this.SNAP_BUF * (TICK_RATE / SNAPSHOT_RATE) * 2;  // = 32 格
if (lastTick >= 0 && entry.tick < lastTick - RESET_GAP) {
  this.snaps = [];          // 清空旧缓冲
  this._serverOffset = null; // 时钟基准重算
  this._interpDelay = 3;
  this._lastRenderAt = 0;
}
```

阈值用 32 格（约 1 秒）而不是"只要变小就重置"，是为了**把普通的乱序包和开局归零分开**：
- 网络乱序最多差一两帧 → 照旧丢弃，不动缓冲
- 开局归零会退回几十格 → 判定为新一局，重置

### 效果（同一套实测）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| tick 停滞段 | **1 处，45 条（3.0 秒）** | **0 处** |
| 渲染游标 lead | -2 → **+62.9** 一路飙 | **-2.6 ~ -0.5 稳定** |
| lead>0 的帧（游标跑到最新快照之后） | **126/241** | **0/241** |
| `frozen` 夹死计数 | 每 250ms 涨 15 次，持续增长 | **恒定 4，不再增长** |
| 开局后车的位置 | — | 位移均匀 0.249~0.252，**零位移帧 0%** |

## 五、测试

17 个测试文件全绿，新增 `test/snapreset.test.mjs`（5 项）：

| 用例 | 钉住什么 |
|---|---|
| 正常递增全部接收 | 别把好包丢了 |
| 轻微乱序（回退 1 格）被丢弃 | **不要误判成新一局**（会白清缓冲闪一下） |
| tick 归零识别为新一局 | 旧缓冲清空、立即接收 tick=2 |
| 归零后 60 条连续接收 | 没有二次冻结 |
| offset 同步重置 | 游标不会一次性超前 |

第 3 条已验证**能被旧代码触发**：

```
AssertionError: 开局后的第一条快照（tick=2）被丢弃了：最新 tick 还是 86，
这会让画面在开局后冻结约 3 秒
```
