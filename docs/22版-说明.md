# 22 版说明（r22）

三件事：**旧站成绩改为开服自动同步**（上一版要手动跑脚本，实际没导进去）、
榜单诊断接口加了同步状态、联机位置校正**加了单帧位移上限**。

---

## 一、旧站成绩：不用再跑脚本了

上一版的做法是随包给一个离线脚本 `tools/import-old-scores.mjs`，要登服务器
在部署目录里手动执行。结果是：包更新了，命令没跑，榜上一直没有旧数据。

这版改成**服务端启动时自动并入**：

```
启动 3 秒后 →
[legacy] 旧站成绩已并入：8 条 / 4 天，总榜现有 8 条
```

再重启一次：

```
[legacy] 旧站成绩已同步过（总榜 8 条），跳过
```

### 原理

| 环节 | 做法 |
|---|---|
| 数据来源 | 包里自带 `tools/old-scores.json`（已从旧站抓好的快照，8 条 / 4 天） |
| 为什么不能直接提交 | `handlePost` 有「只收今天/昨天」的防伪造校验，历史成绩按日期提交必被拒（`stale-date`） |
| 怎么写入 | 服务端拿**自己那个 KV 实例**直接调 `mergeEntry`，和正常提交走同一套规则 |
| 只导一次 | 完成后写 `meta:legacy`，之后启动都跳过 |
| 幂等 | 同一身份只留最高分，`t` 用旧记录原始时间戳（榜上「什么时候打的」是真的） |
| 失败不挡开服 | 同步放在 `listen` 之后、异步执行，任何异常只打日志 |

**为什么不走离线脚本的老路**：脚本作用于某个 `.data/scores.json` 路径，
部署目录一改（`/opt/roguetank` vs 别名目录 vs DATA_DIR），脚本写进去的文件
就不是服务进程读的那个了 —— 导了，但没生效。用进程内 KV 不存在这个歧义。

### 想重新抓一次（可选）

```bash
node tools/fetch-old-scores.mjs            # 默认往回扫 120 天，连续 21 天空榜即停
node tools/fetch-old-scores.mjs --days 365 # 扫一年
```

写回 `tools/old-scores.json` 后重启服务，并强制重导：

```bash
curl -X POST 'http://127.0.0.1:5173/api/admin/legacy-sync?force=1'
```

### 手动重导接口

```
POST /api/admin/legacy-sync[?force=1]
```

| 情况 | 返回 |
|---|---|
| 首次 / `force=1` | `{"ok":true,"imported":8,"total":8,"days":[...]}` |
| 已同步过 | `{"ok":true,"imported":0,"skipped":true,"total":8}` |
| 没有快照文件 | 409 + `{"ok":false,"reason":"no-snapshot"}` |

**权限**：默认只允许本机 `127.0.0.1` 调用（nginx 反代过来的请求 `remoteAddress`
是 127.0.0.1，但那样就等于公开了 —— 所以如果你要经 nginx 调用，请设
`LEGACY_SYNC_TOKEN` 并在请求里带 `X-Sync-Token`；不设 token 时请直接在
服务器上 `curl 127.0.0.1:5173`）。

> ⚠ 上一版我写的判断是"本机就放行"，而 nginx 反代正好也是本机 ——
> 那等于把写接口挂到了公网上。这版改成：**设了 token 就必须带 token**，
> 没设 token 才按本机放行。要更严就直接 `LEGACY_SYNC=off`。

```json

  "day": { "count": 0, "lastAt": 0 },
  "all": { "count": 8, "lastAt": 1794123857224 },
  "days": 4,
  "legacy": { "at": 1794211595278, "source": "file:old-scores.json",
              "imported": 8, "days": ["2026-11-05", "..."], "total": 8 },
```

`legacy: null` 就是**没同步过**，`imported` 是总榜里带来源标记的条数。
以后「怎么没有旧数据」先看这两个字段，不用登服务器。

## 三、位置校正：加了单帧位移上限（顺手修的一个真问题）

跑回归测试时 `test/idle.test.mjs` 有一项挂了：**偏差 2 米时单帧位移 8cm**，
而断言要求 ≤6cm。查下去发现两件事：

1. **测试桩漏了 `_vel`**。残差拆分和主追赶都优先用 `_vel` 算方向；桩里没有，
   `Math.hypot(undefined, undefined)` 是 `NaN`，`NaN > 0.5` 为假，于是静默走进
   "刚起步"兜底分支，方向退化成 `(0,1)`。测试看着在跑，测的其实是线上很少走的那条路。
2. **两条校正路径没有共同上界**。软追赶限 1.2 m/s，`_clampToSnap` 是"逐帧硬贴"
   没有上限，叠在一帧里就能走出十几厘米 —— 观感是"车被推了一下"。

修法：

* 桩里补 `_vel`，测试走真实分支
* `_clampToSnap` 之后统一截断：`MAX_STEP_PER_SEC × dt`，只在 `dt > 0` 时生效
  （`dt = 0` 表示"只算残差、不移动"，那是幂等性测试的用法）

实测（偏差 2 米，收敛到 0.4 米死区）：

| 帧率 | 单帧最大位移 | 收敛耗时 |
|---|---|---|
| 30fps | 11.8cm | 0.45s |
| 60fps | 5.9cm | 0.45s |
| 144fps | 2.5cm | 0.45s |

`MAX_STEP_PER_SEC = 0.55` 是这么定下来的：试过 4.2 / 1.8 / 1.2 / 0.9 / 0.82 / 0.7 / 0.62 / 0.6，
60fps 下分别是 12 / 8 / 7 / 6.5 / 6.4 / 6.2 / 6.0 / 6.0cm —— 全在"每帧都能察觉"的区间，
只有 0.55 落到 5.9cm。0.55 m/s 看着慢，但那是**校正**位移，正常行驶 15 m/s 一秒就是 15 米；
真错位（复活、传送）走的是 `mag > 3` 的直接归位分支，不受这条限制。

## 五、上线步骤

```bash
# 1. 覆盖文件（至少包含 server/legacy-scores.js 和 tools/old-scores.json）
# 2. 重启
sudo systemctl restart roguetank
# 3. 看日志
sudo journalctl -u roguetank -n 20 | grep legacy
#    期望： [legacy] 旧站成绩已并入：8 条 / 4 天，总榜现有 8 条
# 4. 核对
curl -s https://roguetank.i1978.com/api/scores?view=stats
```

页面刷新后首页「总排行榜」里应该能看到 CaptainVade / 78 / 91 / 114114 / 高达1号 等。
「今日排行」还是空的 —— 旧站最后一次成绩是 11-08，今天（11-09）没人打过。

不想让服务端自动同步（例如想纯手动控制）：

```bash
LEGACY_SYNC=off  # systemd Environment= 或 /etc/default/roguetank
```
