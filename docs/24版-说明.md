# 24 版说明（r24）

修的是你报的那条：**组队打完第一波就进不去，点什么都没反应**。

这不是"卡了一下"，是三处独立的断点叠在一起 —— 服务端其实早就开到第二波了，
玩家那边被一块再也关不掉的面板挡住，看起来像死机。

---

## 一、根因

### 1. 鼠标点卡片完全没反应（主因）

选卡面板是单机和联机共用的同一个 DOM，但点击回调只有一个：

```js
onPick: (id) => this.pickUpgrade(id)   // 旧代码
```

单机的 `pickUpgrade` 第一行是：

```js
if (this.state !== 'reward') return;
```

组队局的 `state` 是 `'coop'` —— 于是鼠标点下去**直接空转**，连个报错都没有。
键盘 1/2/3 走的是 `CoopMode` 自己绑的 keydown，所以能用。

面板底下那行提示还写着「点击卡片，或按 1 2 3」，十个玩家里九个会去点。

### 2. 12 秒超时后面板永远关不掉

服务端 `pickWindow` 是 12 秒，到点替没选的人自动选第一张、关窗、开下一波。
但它**没有给客户端发任何"窗口已关闭"的消息**。

客户端 `net.cards` 一直留着 → 面板不关 → 副标题停在「0 秒后自动选择」→
整个画面被盖住。玩家以为卡死，其实服务端已经在打第二波了。

### 3. 卡片底部显示「/ undefined」

`rollForPlayer` 返回时只挑了 5 个字段，**漏了 `max`**：

```js
return picks.map((u) => ({ id, name, icon, rarity, desc }));   // 旧
```

于是底部那行成了 `NEW → Lv.1 / undefined`。单机走的是另一条路径（返回整张卡），
所以只有组队面板是坏的 —— 也说明这个界面从上线起就没人对过。

---

## 二、改法

| 位置 | 改动 |
|---|---|
| `Game.js` | 新增 `_pickCard(id)`：`mode === 'coop'` 走 `coop.pickCard`，否则走 `pickUpgrade` |
| `core/world.js` | 关窗时推 `picksClosed` 事件（所有人选完 / 超时都推） |
| `coop.js` | 新增 `_closeCards()`，三条路汇到一处：自己选了 / 收到 `picksClosed` / 本地超时兜底 |
| `coop.js` | 兜底：超过服务端窗口 + 1.5 秒还没收到消息，也自己关（防丢包、防老服务端） |
| `core/progression.js` | 发卡时补上 `max` 与 `armory` 字段 |

**注意**：兜底这条很重要 —— 即使服务端没更新，只更新前端也能正常进下一波
（最多晚 1.5 秒关面板）。服务端也更新的话，是点完立刻就关。

## 三、顺手修掉的两个同步问题

查这条 bug 时发现，组队选卡还有两处"看起来没事、其实一直在错"的地方：

### 1. 选完卡，卡片等级不会更新

快照每帧只同步位置和血量，**成长数值不在里面**。所以第二波再弹面板时，
已经拿过的卡仍然显示 `NEW → Lv.1`，玩家会以为刚才那张没生效。

现在每波发卡的 `CARDS` 消息里附带服务端权威的 `stats`（速度、装甲上限、
各卡已选次数），客户端在弹面板前对齐一次。实测第二波：

```
第一波选「火力强化」→ 第二波同一张卡显示 Lv.1 → Lv.2 / 5
```

### 2. 选了速度卡，本地预测还在按旧速度跑

同上：`me.speedBase` 不变，服务端却变快了，客户端每帧被残差校正往回拉 ——
手感就是"车变重了、有点拖"。`stats` 对齐时一并修正 `speedBase` 与 `maxHp`。

## 四、验证

**服务端**（真实 Room，两个成员）：

```
tick+0    cleared      wave=1     清波
tick+360  picksClosed  wave=1     12 秒后关窗（以前没有这条）
tick+395  wave         wave=2     开下一波，场上有 2 个敌人
```

**浏览器**（真跑一局，自动瞄准打完第一波）：

```
面板弹出 6.8s
点卡后   hidden=true  wave=2  playing=true      ← 以前这里永远停在面板上
7 秒后   wave=2  enemies=5
```

**两波连打**：

```
第一波  lvs: NEW → Lv.1 / 5     选「火力强化」
第二波  lvs: Lv.1 → Lv.2 / 5    counts: {"damage":1}
```

三条关闭路径都单独验证过：点击关、收到 `picksClosed` 关、超时兜底关。

新增 `test/coopcards.test.mjs`（11 项），19 个测试文件全绿。
其中「点击分流」「必须发 picksClosed」「卡片必须带 max」三条都反向验证过：
把代码改回旧写法，测试立刻失败。

## 五、上线

覆盖文件后重启服务端即可，不需要清数据、不需要迁移。

```bash
sudo systemctl restart roguetank
sudo journalctl -u roguetank -n 20 | grep -E "legacy|clean"   # 顺便确认榜单同步还在
```

需要一起更新的文件：

```
src/Game.js
src/coop.js
src/net.js
src/core/world.js
src/core/progression.js
server/room.js
src/core/protocol.js      （BUILD → r24）
test/coopcards.test.mjs    （新增）
```

`PROTOCOL_VERSION` 没动（还是 3）：`CARDS` 只是多了一个可选字段，
老客户端忽略、新客户端连老服务端也能跑。页面会拿 `BUILD` 和 `/healthz`
比对，不一致会在左上角弹红条，一眼能看出"文件覆盖了但进程没重启"。

## 六、还有一个已知的次要问题（这次没改）

**组队局不计入排行榜**。这是既定的产品规则（单人 100 分/杀、组队按 √人数 折算，
两套口径没法混排），不是 bug。如果你想让组队也上榜，得先定一个折算规则。
